# 게임 시작 422 오류 조사와 수정

> 이 문서는 초기/422 오류 수정 당시의 기록입니다. 이후 변경된 정책과 실제 모델 결과는 [메모리 실험 보고서](MEMORY_EXPERIMENTS.md)를 참고하세요.

검증일: 2026-11-08 (Asia/Seoul).

## 재현된 원인

웹은 `/api/admin/settings`에서 읽은 `Config`를 래핑 없이 그대로 JSON 직렬화해 `/api/admin/validate`와 `/api/admin/start`에 보낸다. 참가자 6명 각각 `id`, `name`, `model`, `role` 필드가 모두 있었다. 직업은 마피아/경찰/의사 각 1명과 시민 3명이며 모두 활성화 목록에 있었다. `GameConfig`의 필수 중첩 필드나 프런트엔드/백엔드 스키마 불일치는 재현되지 않았다.

같은 JSON으로 실제 실행 중인 서버에 요청한 결과:

- `/api/admin/validate`: **200**, `{"valid":true}`
- `/api/admin/start`: **422**, `{"detail":"메모리 보호: deepseek-r1:7b 실행 보류. 현재 스왑 3.57GB. 앱을 정리하거나 경량 태그를 직접 선택하세요."}`

Pydantic 요청 검증 실패의 `detail` 배열이 아니라, `Ollama.guard()`에서 발생한 `ModelError`의 문자열이었다. `main.py`가 모든 `ModelError`를 422로 변환해 정상 설정을 요청 형식 오류처럼 보이게 했다. 당시 가용 메모리는 약 1.4GiB였고, DeepSeek 7B 사전 점검에서 차단됐다. 게임 상태를 생성하거나 모델을 로드하기 전에 발생했다.

원래 브라우저의 과거 네트워크 로그 자체는 확보하지 못했다. 현재 웹이 불러오는 동일 설정과 실제 API 응답으로 재현했고, 수정 후에는 프런트엔드가 사용하는 `startGame()` 함수를 직접 실제 HTTP 서버에 연결해 전송 JSON과 응답을 함께 확인했다. 전체 요청/응답의 로컬 진단 자료는 `reports/local-*`에 보관하며 Git에서 제외한다. 관리자 키는 자료에 기록하지 않는다.

## 변경

- 요청 필드/직업 구성 오류: **422 / invalid_request**. 기존 `detail` 배열 구조를 유지하면서 한국어 `message`와 필드별 `issues`를 추가했다. 요청 본문과 Pydantic `input`, `ctx`를 응답에 되돌려 보내지 않는다.
- 모델 실행 환경 문제: **503**. 메모리 부족은 `insufficient_memory`, Ollama 연결 불가는 `ollama_offline`, 미설치 모델은 `model_not_installed`로 구분한다. 기존 문자열 `detail`은 유지하고 해결 안내 `hint`를 추가했다.
- 직업 검증 규칙과 메모리 보호 기준은 그대로 유지한다. 모델/직업을 자동 교체하거나 메모리 보호를 우회하지 않는다.
- 프런트엔드 오류 패널은 명시적으로 닫거나 다음 작업을 시작할 때까지 남는다. 오류가 생기면 패널로 포커스를 옮기고 수정할 필드/권장 조치와 설정 또는 모델 실험실 이동 버튼을 표시한다.
- 이미 배정된 직업을 끄려 하면 해당 참가자를 안내하고 먼저 배정을 바꾸도록 한다. 보이지 않는 잘못된 직업 값이 선택 상자에 남는 상황을 방지한다.

## 검증

실제 프런트엔드 요청 함수 → 별도 로컬 FastAPI 서버 (임시 DB):

| 요청 | 결과 |
|---|---|
| 정상 6인 구성, 명시적인 Mock 공급자 | **200**, 6인 게임 생성, paused |
| 정상 구성, 실제 Ollama, 현재 메모리 부족 | **503 / insufficient_memory**, 모델 로드 없이 보류 |
| 마피아 0명 | **422**, `players`: 마피아 1~2명 배정 안내 |
| 두 번째 참가자의 `role` 누락 | **422**, `players.1.role`: 직업 필수 항목 안내 |

정상 Ollama 시작 경로는 설치/가용 메모리를 모의한 API 회귀 테스트에서 200으로 확인했다. 현재 Mac에서 실제 Ollama 게임이 시작됐거나 모델이 응답했다고 주장하지 않는다. 메모리 확보 또는 사용자가 선택한 설치된 경량 모델 조합이 여전히 필요하다.

자동 테스트는 요청 직렬화/인증/검증 선행, 낮은 메모리와 오프라인의 503, 정상 Ollama 사전 점검과 Mock 시작, 필수 필드/직업 활성화/직업 수/컨텍스트 범위의 422, 요청 원문 비공개, 한국어 안내와 XSS 방어를 포함한다. 기존 게임 엔진/통계/말투/정보 격리 테스트를 함께 실행했다.
